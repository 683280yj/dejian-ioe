# 04 预期成效的测算思路

> 对应 REQUIREMENT.docx「三 预期成效（需有测算推导过程，需提供回测数据或仿真模拟与原人工基线对比）」。
> **本篇只给方法与公式，不给结果。** 结果必须由系统回测/仿真跑出后填入，并注明数据来源；在德鉴真实数据到位前，用「演示酒业」数据跑出的结果一律标「演示假设」。

## 4.1 指标定义与公式
| 指标 | 公式 | 数据 | 方向 |
|---|---|---|---|
| 缺货次数/月 | 当月出现「可用库存 < 当日需求」的 SKU·日 次数 | D07 D08 | 越低越好 |
| 缺货率 | 缺货 SKU·日 ÷ 总 SKU·日 | D07 D08 | 越低越好 |
| 库存周转次数/年 | 年销售成本 ÷ 平均库存成本；平均库存 =（期初 + 期末）÷ 2 或按日均 | D02 D07 D08 | 越高越好（不以缺货为代价） |
| 库存可售天数 | 当前库存 ÷ 日均需求预测 | D06 D08 | 落在目标区间内 |
| 订货准备耗时 | 从收到客户需求到批发单提交的时长（跟岗计时 / 系统 created_at→submitted_at） | D06 D13 | 越低越好 |
| 采购决策耗时 | 从发现补货需要到采购单提交的时长 | D04 D13 | 越低越好 |
| 对单耗时 | 一期供应商对账从开始到确认/争议的时长（系统 created_at→decided_at + 跟岗） | D11 D13 | 越低越好 |
| 订单差错率 | 发货后修改/退回的订单数 ÷ 发货订单数 | D06 D07 D12 | 越低越好 |
| 对账差异笔数 | 每期 difference ≠ 0 的对账单数及疑似差异单据数 | D11 | 发现率越高越好 |
| 资金占用 | Σ(SKU 库存量 × 成本价) 的日均值 | D02 D08 | 在不增加缺货前提下越低越好 |
| 人工节省工时 | Σ(基线耗时 − 新耗时) × 频次 | D13 + 系统时间戳 | — |
| 采纳率 / 人工改量率 | 被采纳建议数 ÷ 建议总数；采纳后人工修改数量的比例 | ai_assist 建议记录 + D04 | 衡量建议可信度，不追求 100% |

## 4.2 补货测算口径（供仿真复现）
- 日需求预测：移动平均（窗口 w）× 季节指数（月份）。
- 安全库存 SS = z × σ_日需求 × √(提前期天数)。
- 再订货点 ROP = 日需求预测 × 提前期 + SS。
- 建议量 = max(0, 目标库存 − 当前库存 − 在途)，按箱规向上取整，并满足最小起订量。
- 预算约束：多个 SKU 同时触发时，在周预算内按“缺货损失 / 占用资金”排序分配（背包式分配）。
- 以上函数在 `ai_assist/algorithms.py`（lane-a）实现：`moving_average`、`seasonal_index`、`safety_stock`、`reorder_point`、`round_up_to`、`budget_allocate`。
- 参数 w、z（服务水平）、提前期、周预算、箱规的取值，在德鉴配置前全部为「演示假设」。

## 4.3 回测 / 仿真方法
1. **数据准备**：取一段历史出库与库存（真实德鉴数据或「演示酒业」数据），切分为训练窗口与回测窗口。
2. **人工基线轨迹**：用历史上真实发生的采购单（时间、数量）重放库存，得到基线的缺货次数、周转、资金占用。没有真实采购记录时，用 01 篇的人工规则（例如“库存低于某值就补一批”）模拟，且该基线本身标「演示假设」。
3. **AI 建议轨迹**：在回测窗口按 3.4 的周期逐期运行补货测算；假设人**全部按建议采纳**（上界）和**按影子期实际采纳率采纳**（现实情形）各跑一次。
4. **同口径对比**：两条轨迹用 4.1 同一组公式算指标，列出差值与相对变化：相对变化 =（AI − 基线）÷ 基线。
5. **耗时类指标**：不能靠仿真得出，只用 P3/P4 期间的跟岗计时与系统时间戳对比；样本不足时不出结论。
6. **对账类指标**：取历史若干期对账单，用 `match_amounts` 自动匹配，对比人工找出的差异是否被覆盖（召回）与误报数（精确）。
7. **敏感性分析**：对 z、提前期、预算各做上下浮动，观察缺货率与资金占用的此消彼长，向评委说明参数的取舍。

## 4.4 结果呈现规范
- 每个结果写明：数据来源、时间范围、参数取值、是“回测”还是“仿真”。
- 用「演示酒业」数据得出的数字一律标「演示假设」，不得写成德鉴的实际成效。
- 同时报告不利结果（例如资金占用上升、某类 SKU 缺货未改善），并在 05 篇说明原因。
