# 05 适用边界与失效场景

> 对应 REQUIREMENT.docx「三 适用边界、失效场景」。

## 5.1 适用边界
| 维度 | 适用 | 不适用 / 不做 |
|---|---|---|
| 业务 | To B 批发：经销商/企业客户订货、采购补货、供应商对账、应收应付登记 | 零售 POS、电商平台对接、生产/酿造工艺、基酒坛号级管理（规划外） |
| 决策 | 有历史出库数据、需求相对平稳的常销 SKU 补货；规则可解释的异常筛查 | 新品首单、节庆/团购一次性大单、价格策略制定、经销商准入 |
| 执行 | 建议、预警、草稿、金额汇总 | 审批、入库、发货、付款、对账确认——**一律人工**；系统不接任何支付通道 |
| 数据 | 关键字段非空率达标的数据集（阈值「演示假设」） | 未达标的数据集不参与测算，建议中显示“数据不足” |
| 组织 | 有明确岗位与权限（老板/采购/销售/仓库/财务/审计）的团队 | 一人身兼审批与执行时，需老板额外抽查（权限分离失效） |

## 5.2 失效场景与兜底
| # | 失效场景 | 表现 | 识别方式 | 兜底 |
|---|---|---|---|---|
| F1 | 需求突变（节庆、政策、促销、团购大单） | 补货建议偏少，可能缺货 | 实际出库偏离预测超阈值（z-score / IQR 检测） | 建议标“需求异常，请人工判断”；人可改参数重算或直接手工建单 |
| F2 | 历史数据少（新品、新客户） | 预测不可靠 | 数据点数低于窗口长度 | 不出数量建议，只提示人工决策 |
| F3 | 账实不符（漏录入库/发货、盘点差异） | 建议基于错误库存 | 盘点差异、负库存拦截 | 系统拦截库存不足的发货（事务回滚）；先盘点纠正再测算 |
| F4 | 供应商只给总额或口径不一（含税/不含税） | 对账差异无法定位 | difference ≠ 0 且无明细匹配 | 状态只能「争议」，人工向供应商要明细；系统不允许差异非 0 时确认 |
| F5 | 参数配置错误（箱规、提前期、预算） | 建议量离谱 | 人工改量率突然升高 | 参数变更留日志，可回滚；建议必须经人工提交审批 |
| F6 | 人员习惯性“一键采纳” | AI 实际变成自动决策 | 采纳后零修改率长期过高且审批时长极短（阈值「演示假设」） | 老板抽查；审批与入库/发货权限分离 |
| F7 | 外部行情缺失（D14） | 采购择时无依据 | 数据源日期过期 | 行情信号不参与测算，只按库存与需求出建议 |
| F8 | 多租户/多仓配置错误 | 跨品牌数据混用 | 跨租户访问返回 404（已测试） | 按租户隔离查询；仓库字段必填前人工核对 |
